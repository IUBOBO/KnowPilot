> 状态：初始计划 v1.1，已批准统一规划、待执行。Issue [#1](https://github.com/IUBOBO/KnowPilot/issues/1)；阶段 G1；负责人 Retrieval/backend。依据公开源码及现有 Issue，实际开始时核对已合并的最新基线 SHA 和上游契约，记录修订，不预设测试已通过。

## 目标、边界与契约
- 背景、原功能范围、非目标及完整验收：以 [GitHub #1 最新正文](https://github.com/IUBOBO/KnowPilot/issues/1) 为准，不能删减原要求。
- 输入：搜索 API、searchDocuments、EvidencePool、授权查询及旧协议。
- 输出：版本化检索请求/响应与证据定位契约；兼容适配。
- 文件所有权（初始预测，实际路径需核实）：documents/search.ts、agent/evidence.ts、shared 检索/证据类型；app.ts 与 ask-run.ts 由集成负责人协调。
- 开工门禁：G0；硬依赖：无功能 Issue 前置。
- 环境：Node ≥22.19、现有 npm workspaces，独立工作树/测试数据/端口，依赖及模型配置以实际基线为准。

## 源码核对、取舍与恢复
- 复用：`searchDocuments` 已共享 BM25、向量、RRF 和可选重排；`/api/v1/search` 的路由规则为 `knowledge.read`，现有文档检索使用材料和单文档检索策略。
- 边界：在候选收集层实现经确认的授权范围，沿用台账查询的行级授权；逐文档权限若涉及新的策略或数据，先单独确认。复用 `SearchHit`、证据来源版本和 `evidence-restore.ts`，用旧 API/历史答复适配比较兼容。
- 失败与恢复：版本扩展用可选字段或受控适配，出现回归时切回原调用契约；记录新增迁移是否必要。
- 计划前置条件：无功能 Issue 前置；通过 G0。

## 约束与风险
- 将原有环境视为生产运行目录；仅在确认的独立开发工作树中操作。备份与 Git 基线 PR 必须先完成并确认；每个任务使用独立测试库、数据目录、端口与测试凭据。严禁生产库测试、公开密钥/私有科研资料。
- 保持现有 React/TS、Hono、SQLite、Pi Agent、TypeBox；保留权限、引用、预算、续跑、审计与旧数据兼容。共享文件只允许协调后的单写者或串行集成。
- 每个节点完成后对比 Master Plan、当前 Issue 最新正文、该 Plan、节点验收；检查真实差异和测试证据，不以模型自我声明代替测试。偏差先修正再复验；重大范围或接口变化先提案、获得确认并同步计划/依赖。
- 不允许自动合并 PR；人工批准后由协调者按依赖合并，合并后验证最新 main；未验收不得关闭 Issue。
