## v1.2 契约与调用链

开发基线 `07642b4ab8e2c6eae0d3da8107af2ffe5833e3d5`。已核对 [Issue #1](https://github.com/IUBOBO/KnowPilot/issues/1)、Master Plan 和 DAG 中 G0、N1–N3 及 13-B 依赖。

- 旧 `GET /api/v1/search` 响应和 Query 缺省值沿用原协议。显式传 `contractVersion=1` 获取版本化结果。文档示例为 `GET /api/v1/search?contractVersion=1&q=仪器&mode=keyword&material=rule&limit=5&candidateLimit=20&offset=0`。指定 `documentId` 可将候选限制在已获授权的资料内。
- 新旧 HTTP 档和 Agent 文档工具均调用 `retrieveDocumentPage`。该服务将范围交给现有索引策略，在 FTS 截断及向量打分前应用，复用 BM25、向量、RRF 和默认关闭的重排。普通检索执行零 LLM 调用。文档分页只浏览该次排序的候选窗口，不承诺全库总数。后续页沿用原请求的 `candidateLimit`，用 `nextOffset` 续读。Agent 的候选上限、预算、上下文扩展和引用编号维持既有行为。
- 台账示例为 `GET /api/v1/search?contractVersion=1&recordType=M-SUBMIT&status=under_review&limit=5`。四类台账复用 Agent 与既有 repo 的查询接口，按各源自身顺序分页。支持投稿状态、专利阶段、人员状态，以及相应类型既有的分组、关联人员和年份条件。精确 `recordId` 优先于自由文本 `q`，并拒绝列表过滤或非零偏移。数据集现场探测与期刊分区查询保留在原专用工具。V1 检索入口沿用既有 `knowledge.read` 路由授权、共享投稿读取及每个台账的可见范围，检索参数不授予权限。专利精确查询在 SQL 比对范围、ID、删除标记，命中后才装载附属数据。人员仅返回现有 Agent 可用字段，学号不参与候选收集。
- `EvidenceLocator` 以文档 ID、块 ID、索引版本或记录类型、记录 ID、记录版本标识来源。文档结果携带页码、章节、高亮摘录、命中来源及排序分。Agent 直接从候选块回读原文与索引版本，记录版号继续用最新更新时间或专用版本。已归档块仍由既有历史读取路径处理，现有 SSE、答案、引用和检查点协议保留。
- 响应区分请求与实际策略、空结果和诊断。按文档或材料限定时，范围内任一文档索引失败、待建或缺块即报告 `index_unavailable`，可用旧索引报告 `index_stale`，警告可以和当前页命中同时出现。材料范围为空或索引健康但无匹配时，不产生索引警告。语义检索或无关键词命中的混合检索中，实际命中的最高向量得分低于既有阈值时报告 `low_relevance`，包括零分和负分。无语义命中时只报告其他适用的诊断。旧索引、未建索引、向量缺失或不可用、低相关和重排回退均有测试。向量运行失败回退关键词，重排超时回退 RRF。V1 返回通用重排诊断，保留旧响应的既有说明。
- 本 PR 不需要数据库迁移和依赖变更。回滚使用常规 Git revert，不涉及重建、迁移或修改生产数据。
