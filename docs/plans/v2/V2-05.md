# V2-05 初始实施计划 — PDF 内嵌、页码定位与原文高亮

> 状态：初始计划 v1.1，已批准统一规划、待执行。Issue [#5](https://github.com/IUBOBO/KnowPilot/issues/5)；阶段 G2；负责人 PDF viewer。依据公开源码及现有 Issue，实际开始时核对已合并的最新基线 SHA 和上游契约，记录修订，不预设测试已通过。

## 目标、边界与契约
- 背景、原功能范围、非目标及完整验收：以 [GitHub #5 最新正文](https://github.com/IUBOBO/KnowPilot/issues/5) 为准，不能删减原要求。
- 输入：#4 阅读器、授权原件接口、page/quote/excerpt。
- 输出：PDF 阅读插件，可靠匹配高亮及明确回退。
- 文件所有权（初始预测，实际路径需核实）：阅读器 PDF 子组件、授权下载适配；前端 PDF.js 依赖与 worker。
- 开工门禁：G1；硬依赖：#4。
- 环境：Node ≥22.19、现有 npm workspaces，独立工作树/测试数据/端口，依赖及模型配置以实际基线为准。

## 源码核对、取舍与恢复
- 复用：服务端锁文件使用 `pdfjs-dist` 5.4.296（Apache-2.0）；Web 尚无 PDF.js 依赖。现有原件接口返回完整文件。
- 边界：先验证 Web worker、打包和授权取文件，明确大文件加载及取消；物理页号与印刷页号分开匹配。若方案需要更改文件传送协议，先确认范围。
- 失败与恢复：遇到重复文本、扫描件、历史版本或定位不唯一时回到 #4 的页码与摘录视图。
- 计划前置条件：#4 已验收合并。

## 约束与风险
- 将原有环境视为生产运行目录；仅在确认的独立开发工作树中操作。备份与 Git 基线 PR 必须先完成并确认；每个任务使用独立测试库、数据目录、端口与测试凭据。严禁生产库测试、公开密钥/私有科研资料。
- 保持现有 React/TS、Hono、SQLite、Pi Agent、TypeBox；保留权限、引用、预算、续跑、审计与旧数据兼容。共享文件只允许协调后的单写者或串行集成。
- 每个节点完成后对比 Master Plan、当前 Issue 最新正文、该 Plan、节点验收；检查真实差异和测试证据，不以模型自我声明代替测试。偏差先修正再复验；重大范围或接口变化先提案、获得确认并同步计划/依赖。
- 不允许自动合并 PR；人工批准后由协调者按依赖合并，合并后验证最新 main；未验收不得关闭 Issue。
