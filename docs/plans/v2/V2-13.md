## 测试方案
- 通用：`npm run typecheck`；涉及 web：`npm run build -w @knowpilot/web`。现有 server 脚本使用 `npm run <script> -w @knowpilot/server`（先验证隔离配置；不运行有破坏性的固定路径脚本）。
- verify-eval
- verify-citations
- verify-claims
- verify-auth
- verify-knowledge
- verify-context
- verify-trace
- `npm run eval -w @knowpilot/server -- --offline --blockers --root tmp/v2-eval --report tmp/v2-eval-report.json`；经批准执行 #13-A 且基线与规划均已合并后运行，G0 在评测证据经过审查后通过。真实模型测试另行授权，离线需模型时记 `NOT_RUN`。
- 每项测试记载 fixture、实际命令、预期与实际、通过/失败/跳过/未执行；需要新增 UI 测试的条目由本任务选择现有或最小测试方案，不能把未安装框架当成已可运行脚本。
- PR 前逐项验证原 Issue Checklist，记录兼容性及权限回归；涉及 UI 保存不含私有数据的截图。

- 验收对应：Issue 第 1 项见 N1 证据；Issue 第 2 项见 N2 证据；Issue 第 3 项见 N3 证据；Issue 第 4 项见 N1 证据；Issue 第 5 项见 N2 的逐 PR 回归和 N3 的最终报告。开工时核对最新正文排列和适用范围。

## 约束与风险
- 将原有环境视为生产运行目录；仅在确认的独立开发工作树中操作。备份与 Git 基线 PR 必须先完成并确认；每个任务使用独立测试库、数据目录、端口与测试凭据。严禁生产库测试、公开密钥/私有科研资料。
- 保持现有 React/TS、Hono、SQLite、Pi Agent、TypeBox；保留权限、引用、预算、续跑、审计与旧数据兼容。共享文件只允许协调后的单写者或串行集成。
- 每个节点完成后对比 Master Plan、当前 Issue 最新正文、该 Plan、节点验收；检查真实差异和测试证据，不以模型自我声明代替测试。偏差先修正再复验；重大范围或接口变化先提案、获得确认并同步计划/依赖。
- 不允许自动合并 PR；人工批准后由协调者按依赖合并，合并后验证最新 main；未验收不得关闭 Issue。
