# R4 SQLite v38、备份恢复与运维文档 — 初始 Plan

状态为规划待审。负责人为发布协调者指定的任务负责人。[Issue #41](https://github.com/IUBOBO/KnowPilot/issues/41) · [发布 Master Plan](MASTER-PLAN.md) · [依赖图](DEPENDENCIES.json)

## 背景与任务边界

V2 数据结构已到 v38，生产运维需要可复核的升级与故障恢复流程。

整理 v37→v38、运行数据路径、SQLite 一致性备份、原件与索引协调、完整性、恢复、升级回退和日常运维。优先复用已有运维文档，否则使用 docs/operations.md。

## 输入、输出与依赖

- **输入** apps/server/src/db 的迁移与数据库实践、G4/G5 隔离证据、模拟 v37 数据库和合成原件、运行配置说明。
- **输出** 一份包含备份恢复章节的运维手册和隔离演练记录。
- **依赖** 发布规划 PR 经人工审查并合并。可与 R1–R3 并行，汇总时与 R3 核对运行路径。
- **环境** 以规划 PR 合并后的实际主分支为文档实施起点。隔离验证使用合成资料、独立测试库、上传目录和端口。

## 实施步骤

1. 确认数据库、上传原件、索引和配置的存储边界与敏感级别。
2. 制定一致性数据库快照、关联文件归档、访问控制、校验和、恢复目标与故障保全步骤。
3. 用模拟 v37 副本演练备份、向新目录恢复、迁移、失败回滚和重放，核对关键记录及原件对应。

## 测试用例

- R4-T1｜隔离副本的一致性快照恢复后，PRAGMA integrity_check 返回 ok，关键记录和原件指纹一致。
- R4-T2｜v37 副本升级至 v38 后验关键数据与权限，验证失败回滚及重跑证据。全程使用合成资料。

记录候选 SHA、操作或命令、实际结果、适用范围及脱敏证据。测试未执行时按原状态记录。

## 验收标准

- 演练记录包含可追溯的版本、校验和、结果、故障恢复判据与兼容说明。
- 操作步骤保护现有数据库、原件、索引与 .env。实际维护或数据切换有独立授权。

## 文件边界与恢复

使用 SQLite 一致性备份机制，从合成副本恢复到新目录。数据库、原件和索引的对应关系以同次快照或明确的重建步骤记录。仅在授权的维护窗口进入真实恢复。

## 交付物

运维及备份恢复文档、隔离迁移与恢复日志、脱敏校验清单。

## 进度记录

初始交付物随发布规划 PR 审查。实际分支、工作树、验证结果、偏差和发布文档 PR 在执行时回填。
