# R5 敏感信息与发布安全审查 — 初始 Plan

状态为规划待审。负责人为发布协调者指定的任务负责人。[Issue #41](https://github.com/IUBOBO/KnowPilot/issues/41) · [发布 Master Plan](MASTER-PLAN.md) · [依赖图](DEPENDENCIES.json)

## 背景与任务边界

公开源码归档和版本说明可能暴露被跟踪的私有材料，已排除文件也需核对实际归档。

审核 R1–R4 集成文档、R6 的 Release Notes 预览、发布文档 PR 及合并后的实际候选树。记录发现位置和处理结论。

## 输入、输出与依赖

- **输入** R1–R4 候选内容、R6 预览、.gitignore、.env.example、Git 已跟踪树、候选 SHA 和预期源码归档清单。
- **输出** 三段式安全审查记录，分别对应文档初审、合并前复审和合并后实际候选审查。
- **依赖** 初审等待 R1–R4 完成。合并前复审等待 R6 Release Notes 预览。合并后复审等待发布文档 PR 人工批准并合并。
- **环境** 以规划 PR 合并后的实际主分支为文档实施起点。隔离验证使用合成资料、独立测试库、上传目录和端口。

## 实施步骤

1. 审查 R1–R4 的合成示例、配置、链接与归档边界，输出初审问题或通过记录。
2. 加入 Release Notes 后复审精确候选树、发布说明和附件范围；任何未处理的敏感发现都暂停交付。
3. 核对合并后的实际 main SHA、跟踪内容和归档清单，保留审查结论与证据链接。

## 测试用例

- R5-T1｜核对 git ls-tree / git check-ignore 的结果与候选归档清单，复查 .env.example 和常见敏感文件类型。
- R5-T2｜脱敏检查内容和拟发布资产是否有密钥、个人信息、私有资料、数据库、原始 Trace、本机路径。仅记录位置与结论。
- R5-T3｜发布文档合并后复核实际 tree 与已审候选，发现差异则重审受影响内容。

记录候选 SHA、操作或命令、实际结果、适用范围及脱敏证据。测试未执行时按原状态记录。

## 验收标准

- 每次审查可定位到具体 SHA、范围和证据。已知敏感疑点完成处置并复验。
- 冻结候选满足配置占位符和可公开归档边界，未决敏感发现将阻断 R6 的正式操作。

## 文件边界与恢复

复审锁定具体提交和发布说明。重新检查被 Git 跟踪文件和实际拟发布归档。疑似敏感内容只保留脱敏路径和分类，处置后重新审核候选及公开资产。

## 交付物

审查清单、脱敏发现与处置记录、最终 SHA/tree 和归档范围。

## 进度记录

初始交付物随发布规划 PR 审查。实际分支、工作树、验证结果、偏差和发布文档 PR 在执行时回填。
