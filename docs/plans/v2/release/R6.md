# R6 Release Notes、版本标签与 GitHub Release — 初始 Plan

状态为规划待审。负责人为发布协调者指定的任务负责人。[Issue #41](https://github.com/IUBOBO/KnowPilot/issues/41) · [发布 Master Plan](MASTER-PLAN.md) · [依赖图](DEPENDENCIES.json)

## 背景与任务边界

正式发布需用可追溯的版本说明与准确标签绑定已验收候选。当前产品标签方案为 v2.0.0，内部版本字段为 0.1.0。

准备 Release Notes 预览、冻结候选及审批证据。获得针对该候选的明确授权后创建标签和 GitHub Release。

## 输入、输出与依赖

- **输入** 发布计划、G5 报告和已知问题、R1–R4 交付、R5 审查、发布文档 PR 实际合并 SHA、独立人工授权。
- **输出** 先交付 Release Notes 预览和候选核对报告，审批后交付 v2.0.0 标签、Release 与可追溯记录。
- **依赖** 预览等待 R5 初审。冻结候选等待发布文档已合并、R5 合并后审查完成及 R3/R4 定向证据已核对。创建标签和发布各以用户明确授权为条件，发布还要求标签已指向同一候选。
- **环境** 以规划 PR 合并后的实际主分支为文档实施起点。隔离验证使用合成资料、独立测试库、上传目录和端口。

## 实施步骤

1. 归纳功能、升级说明、兼容边界、故障记录及真实模型证据口径，在发布文档 PR 提供预览。
2. 报告产品标签与 package/SERVICE_VERSION 的显示关系。记录三处 main、最终 SHA/tree、部署迁移及恢复证据后提交候选审查。
3. 按独立批准的 SHA 执行标签和正式发布，核对版本说明、解析出的提交及 GitHub 源码归档。

## 测试用例

- R6-T1｜核对 Release Notes 与 G5 已知限制和 #1–#12 实际范围，验证所有公开链接。
- R6-T2｜冻结后确认三处 main 与候选 SHA 一致、tag 未占用、运行及恢复证据覆盖候选。
- R6-T3｜获批执行后核对远程 tag、Release、源码归档和候选 SHA，发现偏差暂停分发。

记录候选 SHA、操作或命令、实际结果、适用范围及脱敏证据。测试未执行时按原状态记录。

## 验收标准

- 版本说明准确说明产品标签 v2.0.0 与内部 0.1.0，版本不一致先报告。package 和 SERVICE_VERSION 保持当前值。
- 标签与 Release 指向同一已批准 SHA，发布记录和归档可追溯。每项发布操作能追到用户授权。

## 文件边界与恢复

冻结后核对三处 main 和计划范围。审批必须覆盖准确 SHA。标签、Release 及归档验证保留实际链接。标签已存在且指向不同提交时暂停，保留现有指向。

## 交付物

Release Notes 预览、冻结候选审核包、获批后的标签和 Release URL 及核对报告。

## 进度记录

初始交付物随发布规划 PR 审查。实际分支、工作树、验证结果、偏差和发布文档 PR 在执行时回填。
