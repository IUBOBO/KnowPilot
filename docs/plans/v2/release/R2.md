# R2 系统与 Agent 架构文档 — 初始 Plan

状态为规划待审。负责人为发布协调者指定的任务负责人。[Issue #41](https://github.com/IUBOBO/KnowPilot/issues/41) · [发布 Master Plan](MASTER-PLAN.md) · [依赖图](DEPENDENCIES.json)

## 背景与任务边界

仓库已有 README、路线图、阶段验收材料及证据回调契约，可将分散的系统说明整理为一个公开入口。

在同一架构文档中说明系统组件和 Agent 执行路径。优先更新已有架构文档，否则使用 docs/architecture.md。

## 输入、输出与依赖

- **输入** README.md、ROADMAP.md、证据回调契约、apps/server/src/app.ts、apps/server/src/agent/ask-run.ts、检索与 shared 协议。
- **输出** 一份系统和 Agent 架构说明，包含边界、权限、数据与事件的路径。
- **依赖** 发布规划 PR 经人工审查并合并。可与 R1、R3、R4 并行。
- **环境** 以规划 PR 合并后的实际主分支为文档实施起点。隔离验证使用合成资料、独立测试库、上传目录和端口。

## 实施步骤

1. 从 Web 入口追到 Hono、SQLite、shared 类型及检索服务，核对每一层的数据职责。
2. 沿 Pi Agent 工具、检索范围、上下文、引用、SSE、预算和续跑核对真实源码。
3. 引用既有证据阅读器契约和 G2–G4 的合成证据说明私有笔记与人工确认入库边界。

## 测试用例

- R2-T1｜沿一条合成范围问答追踪已实现的入口、检索、上下文、答复和证据读取，文档路径逐段匹配代码。
- R2-T2｜复核私有笔记、来源撤权、未确认草稿和真实事件的文字规则与现有证据一致。

记录候选 SHA、操作或命令、实际结果、适用范围及脱敏证据。测试未执行时按原状态记录。

## 验收标准

- 架构与 Agent 执行说明可追到真实的路径、类型或审查证据。
- 外部模型与本地数据边界清楚，架构说明没有重复维护的段落或未经证实的能力。

## 文件边界与恢复

合并系统与 Agent 两条说明到同一文档，引用已有契约和阶段报告。对外展示的流程和数据图采用合成示例，源码路径以当前候选为准。

## 交付物

系统和 Agent 架构文档，以及源码与证据索引。

## 进度记录

初始交付物随发布规划 PR 审查。实际分支、工作树、验证结果、偏差和发布文档 PR 在执行时回填。
