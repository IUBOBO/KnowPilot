# R1 整理 README — 初始 Plan

状态为规划待审。负责人为发布协调者指定的任务负责人。[Issue #41](https://github.com/IUBOBO/KnowPilot/issues/41) · [发布 Master Plan](MASTER-PLAN.md) · [依赖图](DEPENDENCIES.json)

## 背景与任务边界

现有 README 已覆盖快速启动及 V1 能力，需要补充 V2 的入口和发布导航。

修订现有 README 的产品简介、功能入口、环境要求、快速启动、健康检查和文档导航。文件所有权为 README.md。

## 输入、输出与依赖

- **输入** README.md、ROADMAP.md、已验收的 G5 报告、根目录 package.json、R2–R4 最终文档路径。
- **输出** 一个可作为公开入口的 README，保留已有功能和有效操作说明。
- **依赖** 发布规划 PR 经人工审查并合并。可与 R2–R4 并行，跨文档链接在协调者汇总时复核。
- **环境** 以规划 PR 合并后的实际主分支为文档实施起点。隔离验证使用合成资料、独立测试库、上传目录和端口。

## 实施步骤

1. 按实际功能和版本更新产品概述，区分知识检索、智能问答、证据阅读、研究笔记及知识确认。
2. 核对 Node 要求、现有安装和启动命令、健康检查地址及脱敏配置示例。
3. 汇总时复核 R2–R4 链接，复用其技术说明。

## 测试用例

- R1-T1｜从 README 的入口跟随相对链接，核对标题锚点和目标文件。
- R1-T2｜逐项核对命令是否定义于实际 package scripts；按 R3 的隔离演练结果确认快速启动文字与观察一致。

记录候选 SHA、操作或命令、实际结果、适用范围及脱敏证据。测试未执行时按原状态记录。

## 验收标准

- 保留现有有效说明，V2 功能、运行要求、命令和端口有源码或实际运行依据。
- 导航链接可用，README 不含生产账号、内部路径或私有材料。

## 文件边界与恢复

保留 README 上现有安装和功能入口。集成时由协调者合入跨文档链接。发现命令差异时先检查实际脚本和 R3 证据，再修订文档。

## 交付物

README.md 差异，以及链接与运行命令核对记录。

## 进度记录

初始交付物随发布规划 PR 审查。实际分支、工作树、验证结果、偏差和发布文档 PR 在执行时回填。
