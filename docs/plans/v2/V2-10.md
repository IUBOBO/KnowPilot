> 状态：初始计划 v1.1，已批准统一规划、待执行。Issue [#10](https://github.com/IUBOBO/KnowPilot/issues/10)；阶段 G3；负责人 Notes/export。依据公开源码及现有 Issue，实际开始时核对已合并的最新基线 SHA 和上游契约，记录修订，不预设测试已通过。

## 目标、边界与契约
- 背景、原功能范围、非目标及完整验收：以 [GitHub #10 最新正文](https://github.com/IUBOBO/KnowPilot/issues/10) 为准，不能删减原要求。
- 输入：#9 笔记读权限及结构化内容。
- 输出：本地生成 UTF-8 Markdown、可读 PDF，来源清单。
- 文件所有权（初始预测，实际路径需核实）：notes/export 独立模块、导出组件；笔记共享入口协调。
- 开工门禁：G2；硬依赖：#9。
- 环境：Node ≥22.19、现有 npm workspaces，独立工作树/测试数据/端口，依赖及模型配置以实际基线为准。

## 源码核对、取舍与恢复
- 复用：沿用 #9 的私有笔记、来源契约及已通过的读权限；#5 的 PDF 阅读器不承担导出。
- 边界：比较可本地运行的 PDF 渲染方案，冻结字体、公式、长表格、引用与不可访问来源输出规范，提供 UTF-8 Markdown 和隔离样例。
- 失败与恢复：权限改变时再授权或按约定剔除敏感内容，导出失败需明确提示；不用云端转换。
- 计划前置条件：#9 已验收合并；共享笔记入口串行接线。

## 约束与风险
- 将原有环境视为生产运行目录；仅在确认的独立开发工作树中操作。备份与 Git 基线 PR 必须先完成并确认；每个任务使用独立测试库、数据目录、端口与测试凭据。严禁生产库测试、公开密钥/私有科研资料。
- 保持现有 React/TS、Hono、SQLite、Pi Agent、TypeBox；保留权限、引用、预算、续跑、审计与旧数据兼容。共享文件只允许协调后的单写者或串行集成。
- 每个节点完成后对比 Master Plan、当前 Issue 最新正文、该 Plan、节点验收；检查真实差异和测试证据，不以模型自我声明代替测试。偏差先修正再复验；重大范围或接口变化先提案、获得确认并同步计划/依赖。
- 不允许自动合并 PR；人工批准后由协调者按依赖合并，合并后验证最新 main；未验收不得关闭 Issue。
