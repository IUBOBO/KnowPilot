## 约束与风险
- 将原有环境视为生产运行目录；仅在确认的独立开发工作树中操作。备份与 Git 基线 PR 必须先完成并确认；每个任务使用独立测试库、数据目录、端口与测试凭据。严禁生产库测试、公开密钥/私有科研资料。
- 保持现有 React/TS、Hono、SQLite、Pi Agent、TypeBox；保留权限、引用、预算、续跑、审计与旧数据兼容。共享文件只允许协调后的单写者或串行集成。
- 每个节点完成后对比 Master Plan、当前 Issue 最新正文、该 Plan、节点验收；检查真实差异和测试证据，不以模型自我声明代替测试。偏差先修正再复验；重大范围或接口变化先提案、获得确认并同步计划/依赖。
- 不允许自动合并 PR；人工批准后由协调者按依赖合并，合并后验证最新 main；未验收不得关闭 Issue。
