## 执行记录

### N1 · 组件与插槽冻结

- 基线为 PR #16 实际合并提交 `07642b4ab8e2c6eae0d3da8107af2ffe5833e3d5`。G0 离线验收批准后释放 #2。以 `AskPage.tsx`、`Layout.tsx`、`ask-session.ts`、`Modal.tsx`、shared `answer.ts` 的调用链和 Issue #2 为依据。
- 页面布局为「既有导航 | 问答会话、输入与工具栏 | 按需打开的来源栏」。宽屏来源栏为中央内容旁的非模态区域，关闭后恢复中央宽度；窄屏复用可聚焦、可用 Escape 关闭的抽屉。阅读面板只显示既有可定位引用，PDF 阅读器按后续计划接入。
- `AskPage` 保持会话和请求状态。输入、会话历史、回答文章与响应式工作区拆为同目录局部组件。保留 Layout 按用户隔离会话与标签页切换的机制。
- 稳定的局部插槽用 React 回调提供。`renderAnswerBlocks({ response })` 仅接收终态 `AskResponse`；`renderProcess({ steps, elapsedMs, runningSince, warnings })` 接收真实 SSE 派生的只读过程数据；`renderEvidenceReader({ citations })` 接收服务端回填的 `Citation[]`，打开和关闭由页面外壳管理。动态块未接入时无占位文案，查询过程和来源保留现有默认实现。
- 安全 Markdown 仍使用显式 React 元素。扩展围栏代码和行内、块级公式，继续共用 shared 表格解析、引用匹配及查询时间格式。审核后选用 KaTeX（MIT）处理公式，以严格的非可信 MathML 模式按需加载。HTML 继续按纯文本展示；未经确认的链接与文本不自动导航。公式格式错误时按纯文本显示。
- 四层核对。Master Plan G1 的中央会话和三个插槽与 Issue #2 的四项验收对应。本 Plan 的 N1 产物包括本节结构与接口，以及下表的交互矩阵。实施前发现桌面只有覆盖式来源抽屉，拟在 N2 按宽窄屏分开呈现并在 N3 复测焦点和布局。

| 现有输入 | 可见状态与回归核对 |
|---|---|
| 未同意云端处理 / 初始空白 | 保留告知、输入禁用条件、无模型推荐问题。 |
| status / evidence / draft_delta / draft_reset | 更新现有进度和真实步骤，安全渲染草稿，草稿重置立即生效。 |
| verified_final / partial / interrupted | 服务端终态替换草稿，保持对应不确定性提示。中断时只在服务端允许续跑时提供按钮。 |
| failed / 用户停止 | 错误显示可重试；取消只中止本次请求，不提交重复问题。 |
| 历史切换 / 来源 / 复核 / 反馈 | 保留既有请求、数据形状、来源定位和语义复核区别。宽屏和窄屏关闭来源后返回原触发器。 |

### N2 · 问答布局与安全渲染

- `AskPage.tsx` 保持请求与会话状态，`AskConversation.tsx` 分离输入和历史，`AskAnswer.tsx` 分离回答和工具栏。`AskWorkspace.tsx` 提供桌面来源栏与窄屏抽屉。`AskProcess.tsx`、`AnswerSources.tsx` 保留原查询事件和引用呈现。
- `AnswerMarkdown.tsx` 沿用 shared 表格与既有引用定位，补充围栏代码、行内和块级公式。原始 HTML 和未授权 Markdown 链接保持纯文本。代码、宽表格和超长公式仅在容器内滚动。公式使用惰性加载的 KaTeX 0.19.1，输出浏览器 MathML，关闭信任，严格校验，限制输入长度、宏扩展与尺寸。依赖锁只增加 KaTeX 及其传递依赖 commander。两者为 MIT。[KaTeX 发行说明](https://github.com/KaTeX/KaTeX/releases/tag/v0.19.1) · [许可证](https://github.com/KaTeX/KaTeX/blob/v0.19.1/LICENSE) · [安全选项](https://katex.org/docs/options)
- 四层核对。Master Plan 的页面结构和可插拔界面、Issue 第 1 和第 3 项、V2-02 的 N2 范围与实际 Web 差异一致。浏览器回归验证了标题、列表、长报告折叠、表格、代码、公式、危险 HTML 与不可信公式。窄屏只允许容器滚动，页面宽度保持在视口内。桌面来源栏关闭后中央扩展。
