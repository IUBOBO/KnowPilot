## 展示方案

1. 正文结果区用现有中性表面和边框，按文档视图每份资料一张卡，按片段视图每片段一张卡。局部使用内边距、圆角和卡片间距。正文保持正常字重，增加行距和段落间距，不整段加粗。标题为卡片标题，资料类型为辅助标签，页码/章节是位置辅助文字；缺失字段自然省略。保留绿色导航、主操作和选择状态。
2. 对 `segments.hit === true` 继续使用语义 `<mark>`，暖黄色底、深色字、约 600 字重。只在正文结果域调整底色和文本变量，深色模式下配对暖底与深字以确保局部文本对比。正文、元数据、链接和标记的普通字号文本对比度目标为 4.5:1。键盘焦点清楚可见，高亮与正文同时通过底色和字重区分；结构和可访问名称也表达各项角色。
3. 对较长片段采用以内容为界的可复制摘要，初始建议约 180 个文本字素，最后依据合成样例调优并记录阈值。按同一长度口径跨原 segments 截取前缀，裁剪后保留原 `hit` 值，避免截断 Unicode 组合字符或代理对；省略号在高亮外。若截点早于首个真实命中，可扩大到合理邻近的边界，让摘要仍有实际命中，避免因极长无命中前缀而默认展开整片。短片段不显示切换。完整展开按原顺序渲染全部 segments，保留返回文本、分段标记与原返回的边界；不访问 PDF、原文或检索接口。
4. 每个片段独立控制，按 chunkId/版本及现有查询会话边界重置。展开收起用同一原生按钮，使用 `aria-expanded`、`aria-controls` 和稳定内容 ID，保留焦点。与「展开其余 N 个命中片段」并列但语义区分，同文档其余片段也使用相同的摘要组件。`EvidenceViewer` 继续使用原始 excerpt、chunkId、页码与章节，避免拿裁切后的显示文本定位。
5. 复用搜索区域的容器宽度，窄屏和右栏开启时标题、标签、定位和动作自然换行，避免卡片横向溢出。保留复选框可访问名称、原文链接及修饰键行为。测试长标题、连续英文、中文、多段、较长元数据与标签。

| 节点 | 实施与停止点 | 对应验收 |

## 测试计划

| 编号与层次 | 可复现用例和预期 |
|---|---|
| S1 DOM/浏览器 | 同一文档多片段及不同文档，检查标题、类型、页/节、正文和命中，校验卡片分隔、普通字重和准确的命中类 |
| S2 单元 | 短片段、零命中、重复词、多个命中段、截断在命中段、中文与组合字符。展开始终等于原分段拼接，标记仅来源于原 `hit`；省略号未标记 |
| S3 浏览器 | 同页分别展开两卡、展开同文档剩余片段并单独展开一条，再收起；高亮与焦点保持，无网络请求，切换查询/视图后不串卡 |
| S4 浏览器／人工 | 约 360 CSS px 窄屏、宽屏、深色、右侧阅读器展开、长标题与混排。核对可见焦点、对比度、键盘 Tab/Enter/Space 和读屏展开状态，页面无横向溢出 |
| S5 浏览器回归 | 比较按文档/片段顺序、原分页/样本数量、资料多选、跨页选择、仅检索此资料、问答交接及返回、原文入口、页/节定位和 EvidenceViewer。对相同合成输入比较现有接口请求与返回 |
| S6 浏览器／人工 | 无结果、接口部分失败与重试、索引提示、无知识读取/问答权限和原文权限撤销；标题与台账快搜继续可用 |

实施时执行 `npm run typecheck`、`npm run build -w @knowpilot/web`、`node --test apps/web/tests/verify-search-results.mjs`、`node --import tsx apps/web/tests/verify-search-browser.mjs`。按脚本配置 `KP_UI_PLAYWRIGHT` 与可用 Chromium，可补跑既有 `verify-evidence-reader.mjs` 与问答交接覆盖。记录命令、退出码、亮暗色对比结果与脱敏截图。保持同一检索样本的召回、顺序、上下文与引用；UI 优化不声明检索质量提升。

## 风险、恢复及交付

如果颜色模糊了真实命中或展开后改变证据定位，先修正局部样式或裁剪逻辑，再用同一 fixture 复验。功能 PR 可单独 revert 恢复原展示，无迁移、依赖或数据恢复步骤。实施 PR 附测试记录、复现步骤、截图和已知限制。当前仅完成源码核对与初始规划，功能测试未执行。
