## 目标与实际调用链

主线没有独立的「数据复核」批量页面或同名按钮。需求落到智能问答「复核依据」，与管理端「知识审核」的冲突裁决及台账无关。

1. `/ask` → `AskPage` → `AskAnswer` → 带引用时渲染 `AnswerEvidenceReview`，以 `runId` 区分实例。现有按钮无云端同意时禁用，选中对象由当前回答决定，没有多选。[AskPage.tsx](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/web/src/pages/AskPage.tsx) · [AskAnswer.tsx](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/web/src/pages/ask/AskAnswer.tsx)
2. 现有 `submit()` 同步设置 `active` ref 和加载，调用 `apiPost<AskEvidenceReview>`，POST `/api/v1/ask-records/:runId/review`，发送 `{ answer, consentConfirmed: true }`，卸载时通过 `AbortController` 停止等待。现有 UI 显示逐条判定、原文摘录、费用和未纳入引用数。[api.ts](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/web/src/api.ts)
3. Hono 鉴权路由要求 `chat.use`，handler 检查登录、运行归属、输入同意和正文。服务 `reviewAnswer` 再检查 Trace 归属，按现有文档、版本及台账可见范围回读证据，受现有字符预算限制。全不可用返回错误，部分不可用通过 `unavailableSourceCount` 表达。将问题、回答和可回读证据发给已配置的 DeepSeek 推理模型，使用现有超时和用量记录，返回带原文核验的最多六条结论。没有批量结果协议，也没有变更正文、原件或业务记录的事务。[路由权限](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/server/src/auth/routes.ts) · [Hono handler](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/server/src/app.ts) · [reviewAnswer](https://github.com/IUBOBO/KnowPilot/blob/97e9cbef279415f7f62f85f221f10c11d10e5305/apps/server/src/agent/answer-review.ts)

## 确认交互与状态

- 点击「复核依据」仅打开 `ConfirmDialog`，保留已有云端同意。展示该轮问题或足以辨认的回答标识、当前候选引用数、实际仅复核可读取证据与可能产生 Token 用量及费用。说明发送的数据以及原回答和资料不变。避免展示未经请求确认的费用或实际命中数。
- 状态为待操作 → 待确认 → 提交中 → 已完成或失败。待确认时「取消」、Esc 和遮罩关闭统一走取消逻辑，发出零请求，焦点回到触发按钮；初始焦点落在取消。确认时重新检查同意、当前轮、正文和候选引用，确认中的目标失效则关闭或禁用并提示用户重新发起。切换作答或离开问答时清理旧弹窗，避免常驻问答工作区在其他路由出现弹窗。
- 提交前同步获取现有 `active` ref 请求锁，锁覆盖快速双击、键盘和同一轮在途重入。按钮显示「正在复核…」，宣布加载状态。禁用取消和确认，并在该调用点阻止 busy 时 Esc 与遮罩关闭（通用 Modal 仍会调用 onClose）。禁用按钮后把焦点保持在弹窗内，完成后关闭并聚焦结果或错误。结果只应用到发出请求的当前实例。卸载后的中止或晚到结果不跨轮显示。
- 无选择指当前回答没有引用，维持入口不出现；未同意时保持禁用。弹窗打开后切换回答或撤回同意时失效。来源在确认前或在途变动仍由后端按当前可见性判断，不新建预检 API。401/403 显示登录或权限提示，404 显示运行或引用不可用；用户应重新进入有效回答，再决定是否复核。
- 部分来源不可用时显示对应计数和实际返回的逐条结果。全部来源不可用或无可核对的结论遵循现有错误。网络超时或中途离开时结果可能未知，说明模型请求可能已发出并计量；不自动重试，不承诺取消计费或服务端跨标签页幂等。可重试错误沿用 `ErrorNotice`，重试入口重新打开确认框，仍使用现有错误元数据和权限。

## 实施节点与验收

| 节点 | 实施与停止点 | 对应验收 |
|---|---|---|
| N1 | 确认真实对象、边界及提示文案，落实打开与取消 | U1、U2。进入或取消操作没有 POST，文案对应真实模型处理 |

| N3 | 跑完整交互、权限和无障碍回归，交付复现记录 | U1–U6、主线回归及人工截图。独立审查和验收后方可合并 |

## 测试计划

| 编号与层次 | 可复现用例和预期 |
|---|---|
| U1 单元／组件状态 | 无引用、云端同意撤销、空正文、切换 runId、离开问答，状态不允许提交旧对象。若状态逻辑直接留在组件，利用现有问答 fixture 验证这些最小行为，不引入测试框架 |
| U2 浏览器 | 点入口、点取消、Esc、点击遮罩，各捕获零次请求。验证焦点初始位置、Tab/Shift+Tab 循环及关闭后的焦点归还 |
| U3 浏览器 | 确认后捕获恰好一次原请求路径和请求体。延迟响应期间尝试双击、键盘、Esc、遮罩及再次提交，确认重复请求数为零；晚到响应不显示在新回答 |
| U4 组件／浏览器 | 替身返回完整、部分未纳入、全量不可用、无有效结论，显示实际结论、提示、费用和错误，未改其他回答记录 |
| U5 API 回归／交互 | 过期登录、403、其他运行归属或失效来源 404、网络断开/超时。核对服务器拒绝时替身未调用、超时提示、无自动重发；可重试项只有再次确认后发新请求 |
| U6 人工 | 桌面及窄屏验收确认、取消、加载、部分结果、权限错误和超时；对键盘及读屏核对标题、忙碌、结果、错误及焦点；同时验证同一回答引用、来源侧栏和反馈 |

实施时执行 `npm run typecheck`、`npm run build -w @knowpilot/web`、`npm run verify-answer-review -w @knowpilot/server`、`npm run verify-auth -w @knowpilot/server`、`node apps/web/tests/verify-ask-shell.mjs`。按现有脚本配置 `KP_UI_PLAYWRIGHT` 和隔离环境。记录基线与候选结果、命令和退出码，并留存脱敏截图。真实模型测试需另行授权和预算。

## 风险、恢复及交付

问题或来源已变时重新打开确认，不重复已完成的复核；遇同类失败按项目规则暂停，记录触发条件后修正复验。UI 回归可单独 revert 功能 PR，无迁移和数据库回滚，现有已发生的用量由原有记录保留。实施 PR 附验收清单、截图、回归日志、实际改动与限制。当前仅完成源码核对与初始规划，功能测试未执行。
