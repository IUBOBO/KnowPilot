# UX-05 科研台账与管理后台信息层级优化

[#50](https://github.com/IUBOBO/KnowPilot/issues/50) · 独立分支 `codex/ux-05-ledger-admin` · 等待 UX-03 [#48](https://github.com/IUBOBO/KnowPilot/issues/48) 全局配色和内容角色冻结。可与 UX-04 并行。输入为现有工作台、台账/后台组件、路由与已冻结主题。输出为紧凑一致的列表、指标和详情。

本 Plan 待人工审查。基线为 `0a2b73e7049bd692d3412b964a822b59428db57b`，含 UX-01 和 UX-02。实施各用独立分支、工作树、合成资料和隔离验证。逐页问题与目标见 [全站检查矩阵](VISUAL-AUDIT.md)，依赖和文件责任见 [UX Master Plan](MASTER-PLAN.md)。实施时重新核对最新验收基线。保留业务入口、权限、证据及数值，前后端协议、数据库与发布范围不变。

## 文件和实施边界

- 按矩阵核对 `HomePage`、`DocumentsPage`、`SubmissionsPage`、`JournalsPage`、`PatentsPage`、`ThesesPage`、`PeoplePage`、`LedgerImportsPage`、`CodePage`、`UploadPage`，以及 `AdminHomePage`、`AdminTracePage` 两个路由、`AdminFeedbackPage`、`UsagePage`、`AdminUsagePage`、`PatrolPage`、`UsersPage`、`ConfigPage`。核对 `RecordEdits`、`PersonPicker` 和台账专项弹窗/表格。候选修改限这些页面及其局部样式，具体接受矩阵的保留判断。
- 将主要名称、字段标签、实际值、指标、状态和辅助信息分层。表格保留结构与现有列，检查表头、行分隔和紧凑行高；局部列用 `tabular-nums` 和明确单位，保留原始格式、数值与精度。状态用文字、标记和语义色共同表达。对长文件名、路径、编号和错误正文采用局部换行/滚动或原有完整详情。避免给常规记录新增一层卡片。
- `index.css`、`a-theme.css` 与通用 `Modal` 等由 UX-03 冻结。使用原组件，只把内容类加在本页或专项组件；保留原筛选、排序、上传进度、权限和每个操作。只读复核共享接口、后端、路由守卫和模型。需要跨所有权时由协调者串行评审调整。

## 节点与验收

| 节点 | 实施 | 放行条件 |
|---|---|---|
| N1 | 建立台账代表页与管理代表页的标注和样例 | 至少一条普通记录、长名称、警告或错误、数值与时间可区分 |
| N2 | 迁移表格、详情、表单、状态和指标 | 逐页矩阵记录改动或保留原因，亮暗与 360px 未丢入口、字段、单位、状态或键盘焦点 |
| N3 | 定向功能回归和代表前后图 | 工作台/台账/配置或 Trace 的同样例对照，验证权限、现有功能和 ≥4.5:1。两任务验收后执行一次共同视觉核对 |

执行 `npm run typecheck` 与 `npm run build -w @knowpilot/web`。浏览器用同数据、同回答、同视口与同主题截图，记录实际命令、退出码和例外。沿用现有独立合成资料与模型替身，正式验收以本任务定向回归为准。G0–G5 全量、真实模型和线上资料不参与。 复用现有 `verify-auth`、`verify-ledger`、`verify-ledger-import`、`verify-ledger-export`、`verify-upload` 或 `verify-trace` 中实际受影响的脚本，并在隔离库上补角色、空态、长路径、详情和错误的局部浏览器回归。禁止对真实资料上传、导入或调用模型。可独立 revert，无数据回滚。
