## 文件和实施边界

- `pages/AskPage.tsx`、`AsksPage.tsx`、`pages/ask/{AnswerMarkdown,AskAnswer,AnswerSources,AnswerBlocks}.tsx` 和 `{ask,answer-blocks}.css`。同一已生成回答按章节、段落和列表分隔，正文约 15–16px、行距约 1.8，宽度约 60–72ch 随容器收敛。用局部类为已解析的 Markdown 加粗提供重点字色和字重。引用编号保留链接、原 ID、可访问名称和定位。表格、代码、数学公式和动态块采用各自的可读滚动及换行，复核确认与忙碌焦点保持。
- `SearchPage.tsx`、`pages/search/{SearchDocuments.tsx,search.css}`、`ChunkPage.tsx`、`components/evidence/{EvidenceViewer.tsx,PdfPreview.tsx,evidence-viewer.css,pdf-preview.css}`。检索已有 15px/1.8，优先只接 Token 并回归。卡片、分页、多选、展开和问答交接保持。命中仅消费 `segments.hit`、已验证摘录或现有 PDF 高亮定位。整块上下文选中态与真实命中分开，历史、撤权、无页码与 PDF 降级保留。禁止把回答重点、证据出处或整段选中文本伪装成命中。
- `ResearchNotesPage.tsx`、`pages/notes/notes.css`、`KnowledgePage.tsx`、`KnowledgeReviewPage.tsx`、`pages/knowledge/{DraftEditor,DiscoveryPanel}.tsx`、`OrganizePage.tsx`。区分编辑/阅读、关联问答/来源、草稿/正式知识、来源/条件/状态、新旧内容/冲突原因/裁决，以及用户描述/Agent 回复/计划/预览/风险。共用全局样式只读，需要新规则时放该页面域的局部样式。
- 保持现有 React 渲染、Markdown 安全路径和文本/数字/证据完整性。使用已有回答和合成内容，不修改 Prompt、Agent Loop、检索或后端。既有问答测试和 UI fixtures 由本任务负责，UX-05 不编辑这些文件。

## 节点与验收

| 节点 | 实施 | 放行条件 |
|---|---|---|
| N1 | 以问答、检索及阅读器应用冻结主题，校准标题、引用和行宽 | 对照同一份回答和检索片段，验证真实命中与普通强调区分，阅读器开合时可读 |
| N2 | 迁移笔记、知识、草稿、发现、审核和整理 | 矩阵逐行核对，合成新旧冲突、跨页/撤权、整理预览和长文本无内容变更 |
| N3 | 各视口回归和图证 | 同数据/回答/视口的亮暗对照，右栏与窄屏。清点所有子页、空态及不改项，记录键盘和普通字号对比度 ≥4.5:1 |

执行 `npm run typecheck` 与 `npm run build -w @knowpilot/web`。浏览器用同数据、同回答、同视口与同主题截图，记录实际命令、退出码和例外。沿用现有独立合成资料与模型替身，正式验收以本任务定向回归为准。G0–G5 全量、真实模型和线上资料不参与。 使用现有 `verify-ask-shell.mjs`、`verify-answer-blocks.mjs`、`verify-ask-process.mjs`、`verify-search-results.mjs`、`verify-search-browser.mjs`、`verify-evidence-reader.mjs` 和 `verify-pdf-preview.mjs` 中受影响流程。按脚本加载 Playwright 并使用不同本地端口和合成样例。缺少整理页可视覆盖时用合成流程补局部 fixture。回滚独立 revert。截图优先选问答、检索右栏、知识审核或整理代表态，其余保留矩阵结果。
